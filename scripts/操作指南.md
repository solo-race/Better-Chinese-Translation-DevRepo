# 脚本操作指南

本指南面向需要运行《Rain World 中文本地化》项目开发脚本的人员。文中包含环境要求、安装步骤、脚本用途、常用命令、运行顺序、报告解读与常见问题。

---

## 1. 环境要求

- 操作系统：Windows / macOS / Linux 均可。
- 建议使用 Python 3.10 或更高版本。
- 项目自带虚拟环境，路径为 `.venv`。
- 脚本依赖：
  - 仅使用 Python 标准库，不要求安装第三方包。
  - 平台可能存在 PEP 668 限制（系统 Python 禁止直接安装包），因此统一通过 `.venv` 运行。
- 项目文件结构：
  - `Dev/Raw-texts/`：官方原始文本，只读，不应修改。
  - `Dev/Dev-texts/`：本地修改/待审校文本。
  - `scripts/`：脚本与报告目录。
  - `scripts/reports/`：脚本生成的报告目录；该目录已被 `.gitignore` 忽略，不会提交。

## 2. 环境准备

在项目根目录打开终端，执行：

```bash
python3 -m venv .venv
```

验证虚拟环境：

```bash
.venv/bin/python --version
```

Windows PowerShell 下使用：

```powershell
.venv\Scripts\python --version
```

以下命令均以项目根目录为工作目录，并使用 `.venv/bin/python` 运行脚本。

## 3. 脚本一览

| 脚本 | 用途 | 默认报告 |
|---|---|---|
| `check_missing_strings.py` | 检查官方字符串中缺少的键 | `scripts/reports/missing_strings_report.txt` |
| `compare_official_file_counts.py` | 比较官方英文/中文文本文件数量 | `scripts/reports/official_file_count_report.txt` |
| `compare_official_strings.py` | 比较官方英文/中文 `strings.txt` 内容 | `scripts/reports/official_strings_comparison.txt` |
| `check_item_translation_consistency.py` | 检查重复物品/生物名称的中文翻译一致性 | `scripts/reports/item_translation_consistency_report.txt` |
| `check_dev_dialogue_character_names.py` | 扫描开发文本对话中的角色名拼写一致性 | `scripts/reports/dev_dialogue_character_names_report.txt` |

## 4. 通用命令行参数

以下参数在多数脚本中可用：

- `--out PATH`：指定报告输出路径。
- `--no-file`：只在终端打印报告，不写入文件。
- 部分脚本有专属参数，见下文各脚本说明。

退出码约定：

- `0`：未发现问题。
- `1`：发现问题。
- `2`：输入路径错误、文件读取失败或报告写入失败。

## 5. 各脚本使用说明

### 5.1 检查官方缺少的字符串

```bash
.venv/bin/python scripts/check_missing_strings.py
```

用途：找出官方文件中存在、但开发文件 `Dev/Dev-texts/text_chi/strings.txt` 中缺失的键。

可选参数：

```bash
.venv/bin/python scripts/check_missing_strings.py \
  --dev Dev/Dev-texts/text_chi/strings.txt \
  --out scripts/reports/missing_strings_report.txt
```

- `--dev PATH`：指定要检查的开发字符串文件；默认值为 `Dev/Dev-texts/text_chi/strings.txt`。
- `--out PATH`：报告输出路径。
- `--no-file`：仅终端输出。

报告中的 `[MISSING]` 表示官方有但开发文件没有的键。

### 5.2 比较官方文本文件数量

```bash
.venv/bin/python scripts/compare_official_file_counts.py
```

用途：比较官方英文与中文文本文件数量，并列出英文独有/中文独有文件。

报告会列出：

- 总文件数。
- 英文文件数与中文文件数。
- 英文独有文件。
- 中文独有文件。
- 已经排除的目录（如 More Slugcats 约会模拟器目录）。

可选参数：

```bash
.venv/bin/python scripts/compare_official_file_counts.py --no-file
```

### 5.3 比较官方英文与中文 strings.txt

```bash
.venv/bin/python scripts/compare_official_strings.py
```

用途：比较官方英文与中文字符串文件的键和值。

默认只列出键级差异：

- 英文独有键。
- 中文独有键。
- 值相同的键（信息性）。
- 值不同的键。

如需列出全部有值差异的键，加参数：

```bash
.venv/bin/python scripts/compare_official_strings.py --show-value-differences
```

可选参数：

- `--show-value-differences`：逐条列出英文值和中文值不一致的键。
- `--out PATH`：报告输出路径。
- `--no-file`：仅终端输出。

### 5.4 检查重复物品/生物名称的一致性

```bash
.venv/bin/python scripts/check_item_translation_consistency.py
```

用途：检查同一英文名称在官方 `strings.txt` 中重复出现时，中文翻译是否一致。例如 `Five Pebbles` 在基础游戏与远征中的中文翻译不一致时，脚本会标记。

报告中的：

- `[INCONSISTENT]`：同一英文名称在不同文件中使用了不同中文翻译。
- `[CONSISTENT]`：同一英文名称在所有文件中使用了相同中文翻译。

可选参数：

```bash
.venv/bin/python scripts/check_item_translation_consistency.py --no-file
```

### 5.5 扫描开发文本对话中的角色名

```bash
.venv/bin/python scripts/check_dev_dialogue_character_names.py
```

用途：扫描 `Dev/Dev-texts/text_chi/` 下的对话文本和广播头，标记角色名称拼写不一致。

报告中的：

- `[VARIANT]`：角色名称与规范写法不同的拼写。
- `[UNMAPPED]`：无法识别的角色名，通常表示新角色或需要补充别名的角色；不会静默忽略。

可选参数：

```bash
.venv/bin/python scripts/check_dev_dialogue_character_names.py --no-file
```

## 6. 推荐的运行顺序

建议在每次游戏更新后，按以下顺序运行全部脚本：

```bash
cd [Local_Project_Folder_Location]/bettercntrans

# 1. 检查官方字符串中缺失的键
.venv/bin/python scripts/check_missing_strings.py

# 2. 统计官方英文/中文文件数量差异
.venv/bin/python scripts/compare_official_file_counts.py

# 3. 比较官方英文/中文 strings.txt
.venv/bin/python scripts/compare_official_strings.py

# 4. 检查重复英文名称的中文翻译一致性
.venv/bin/python scripts/check_item_translation_consistency.py

# 5. 扫描开发对话中的角色名一致性
.venv/bin/python scripts/check_dev_dialogue_character_names.py
```

运行完成后，检查：

- 每个脚本的退出码是否为 `1`。
- `scripts/reports/` 下对应的报告文件是否已更新。
- 重点查看报告中的 `[MISSING]`、`[INCONSISTENT]`、`[VARIANT]`、`[UNMAPPED]` 标记。

## 7. 报告文件说明

| 报告文件 | 内容 |
|---|---|
| `missing_strings_report.txt` | 官方有但开发文件缺少的字符串键 |
| `official_file_count_report.txt` | 官方英文/中文文件数量与独有文件 |
| `official_strings_comparison.txt` | 英文/中文字符串键、值差异 |
| `item_translation_consistency_report.txt` | 重复物品/生物名称的中文翻译一致性 |
| `dev_dialogue_character_names_report.txt` | 开发对话中角色名拼写与未映射角色 |

## 8. 常见问题

### 8.1 在 Windows 上如何运行？

```powershell
.venv\Scripts\python scripts\check_missing_strings.py
```

### 8.2 脚本找不到文件怎么办？

确认当前目录为项目根目录，或使用绝对路径运行脚本。脚本内部通过 `Path(__file__)` 定位仓库根目录，因此从项目目录外运行也可正常工作，但输入文件路径以脚本常量中的相对路径为准。

### 8.3 报告没有生成？

检查 `scripts/reports/` 目录是否存在写权限。脚本会自动创建目录。若使用 `--no-file`，则不会生成报告文件。

### 8.4 新增了官方文件，脚本不识别？

脚本中的文件列表是固定路径常量。如果游戏更新导致新增官方字符串文件，需要更新脚本顶部的文件列表常量：

- `check_missing_strings.py`：`OFFICIAL_FILES`
- `compare_official_file_counts.py`：`SOURCE_GROUPS`
- `compare_official_strings.py`：`STRING_SOURCES`
- `check_item_translation_consistency.py`：`STRING_SOURCES`

### 8.5 新角色没有被识别？

`check_dev_dialogue_character_names.py` 会将新角色报告为 `[UNMAPPED]`。确定角色后，在该脚本顶部的 `CHARACTER_GROUPS` 中补充该角色的英文名和中文别名即可。

## 9. 注意事项

- 所有脚本都是只读的，不会修改 `Dev/Raw-texts/`、`Dev/Dev-texts/` 或 `Release/` 中的文本内容。
- 报告文件位于 `scripts/reports/`，已被 `.gitignore` 忽略。
- 不要手工修改 `Dev/Raw-texts/` 下内容；该目录是官方参考基线。
- 若脚本输出异常，请保留终端输出与报告文件，以便排查。
